# 비트코인 강화학습 매매 (P0)

차트 지표(이동평균·거래량·RSI·MACD 등)를 4시간마다 보고 **현금 / 비트코인** 중 무엇을 들고 있을지
스스로 판단하는 강화학습 에이전트와, 그것을 "과거에 맞추지 않은 방식"으로 검증한 백테스트입니다.

결과 요약은 [../btc.html](../btc.html) (사이트: `btc.html`)에 있습니다. 이 문서는 방법과 실행법입니다.

---

## 1. 무엇을 보고 판단하나 — 22개 지표

4시간봉(UTC 00·04·08·12·16·20시 = 한국시간 09·13·17·21·01·05시)마다 아래 지표를 계산합니다.
가격 수준과 무관한 숫자로 바꿔서 넣기 때문에, 비트코인이 1천 달러일 때와 10만 달러일 때 같은 모양의 차트는
같은 입력이 됩니다. **학습 데이터로 맞춘 정규화 상수가 하나도 없어서** 미래 정보가 섞일 틈이 없습니다.

| 분류 | 지표 |
|---|---|
| 수익률 | 1봉·1일·1주·1달 수익률 (변동성 σ로 나눔) |
| 이동평균 | 종가 vs 20·50·200봉선, 1200봉(≈200일)선 / 50-200 교차, 300-1200(≈일봉 50-200) 교차 |
| RSI | RSI14 (4시간봉), RSI84 (≈일봉 RSI14) |
| MACD | MACD(12,26,9) 선·히스토그램, 일봉 환산 MACD(72,156,54) 히스토그램 |
| 거래량 | 직전 180봉 평균 대비 이번 봉 거래량, 20봉/180봉 거래량 추세, 상승·하락봉 거래량 흐름 |
| 변동성·봉 모양 | 변동성 국면(단기/장기 σ), 봉 길이(고가/저가), 종가 위치(CLV), 1달 고점 대비 낙폭 |

거기에 **거래비용 c** 한 칸이 더 들어갑니다(아래 3절).

## 2. 어떻게 배우나 — Double DQN, 비용 분해

상태 = (지표 22개, 지금 들고 있는 것 p), 행동 a = 현금(0) 또는 코인(1).

작은 계좌는 시장 가격을 움직이지 못하므로, 내가 무엇을 하든 다음 차트는 똑같이 옵니다.
그래서 가치함수가 **정확히** 두 부분으로 나뉩니다.

```
Q(s, p, a) = κ·|a − p|·ln(1 − c)   +   U(s, c, a)
             └ 지금 갈아타는 비용 ┘     └ a를 들고 앞으로 갈 때의 가치 (신경망) ┘

U(s, c, a) = κ·a·m  +  γ · max_a' [ κ·|a' − a|·ln(1 − c) + U(s', c, a') ]
m = ln(다음다음 봉 시가 / 다음 봉 시가),  κ = 100,  γ = 0.97 (약 5.5일 앞까지 봄)
```

- **행동 보강**: 두 행동의 목표값을 표본마다 모두 정확히 계산할 수 있어 무작위 탐험이 필요 없습니다.
- **판단 규칙**: 현금이면 `U1 − U0 > −κ·ln(1−c)`일 때 매수, 보유 중이면 `U1 − U0 < κ·ln(1−c)`일 때 매도.
  비용만큼의 문턱이 저절로 생겨 잔매매를 하지 않습니다.
- **신경망**: 23 → 32 → 32 → 4 (ReLU), 5개를 따로 초기화해 평균(앙상블). numpy로 직접 구현(`nn.py`).
- 보조 출력(앞으로 1일·1주 수익률 예측)은 규제용이며 판단에는 쓰지 않습니다.

솔직하게 말하면, 이 구조에서 "강화학습"은 **다음 몇 봉의 기대수익 예측 + 비용을 고려한 최적의 갈아타기 문턱**
입니다. γ=0(당장 다음 봉만 보는 버전)과 비교해 미래를 내다보는 부분이 실제로 도움이 되는지도 격자 실험에서 봅니다.

## 3. "과거에 맞추지 않았다"는 것을 어떻게 보장하나

학습하는 시스템이 과거 데이터를 전혀 안 쓸 수는 없습니다. 대신 다음을 지켰습니다.

1. **시간은 앞으로만** — 2017-01부터 매월 1일, 그때까지의 데이터로만 모델을 갱신하고(1월은 처음부터,
   나머지 달은 이어서 300스텝), 그 달 동안은 그 모델로만 판단합니다. 실운용과 똑같은 흐름입니다.
   학습 데이터는 갱신 시점보다 43봉(약 7일) 앞에서 끊습니다.
2. **체결은 다음 봉 시가** — 종가를 보고 그 종가에 살 수는 없으니까요 (이 저장소 원칙).
3. **설정은 결과를 보기 전에 고정** — 주 전략 P0의 모든 값은 사전 등록했고, 유일하게 데이터로 정한 것은
   학습 스텝 수(2014~2016 검증 손실로, 손익은 보지 않고 2000스텝)입니다.
4. **여러 번 돌려 중간값을 보고** — 시드만 다른 10번의 워크포워드 중 **5번째(작은 쪽 중앙값)**를 보고합니다.
   가장 좋은 시드를 고르지 않습니다.
5. **시험한 것은 전부 셉니다** — 격자 12개 + 절제 3개 + 예산연구 9개를 모두 기록(`data/btc/runs/trials.jsonl`)하고,
   디플레이티드 샤프(DSR)와 과최적화확률(PBO)로 "여러 개 중 잘 나온 걸 고른 효과"를 걷어냅니다.
6. **잠금 구간** — 2025-01-01 이후는 코드가 `BTC_LOCKBOX_OPEN=1` 없이는 계산을 거부하고, 열 때마다
   `data/btc/lockbox_audit.log`에 남습니다. 모든 설정을 확정한 뒤 한 번만 열었습니다.
7. **16개 격자** — 4시간봉 경계를 15분씩 밀어 만든 16가지 봉으로 학습해 특정 봉 모양을 외우지 못하게 했고,
   결과도 16개 격자 모두에서 확인합니다.
8. **대조 실험** — 예측력을 심어 둔 합성 시장에서는 이겨야 하고(양성 대조), 예측력이 없는 GARCH 시장
   10개에서는 이기면 안 됩니다(음성 대조). 무작위 정책·특징 섞기·시간 이동 귀무모형과도 비교합니다.

## 4. 파일

| 파일 | 하는 일 |
|---|---|
| `data.py` | 1분봉 → 15분봉 캐시(`data/btc/btcusd_15m.csv.gz`), 15분봉 → phase별 4시간봉, 죽은 봉 처리 |
| `features.py` | 22개 지표 — 봉 하나씩 갱신하는 엔진 (백테스트와 실시간이 같은 코드) |
| `env.py` | 체결 회계 (다음 봉 시가 체결, 비용, 일별 평가) — 보상·백테스트·기준전략·모의매매 공용 |
| `nn.py` | numpy 신경망 (앙상블을 한 번에 계산), Adam |
| `agent.py` | DDQN-AA 학습기, 판단 규칙 |
| `config.py` | P0 설정, 격자 12개, 절제 3개, 비용 시나리오 |
| `walkforward.py` | 매월 재학습 워크포워드, 안전 점검, 예산 연구, 온라인 학습(X2) |
| `evaluate.py` | 성과·기준전략·통계검정·선택기·귀무모형 → `data/btc/report_*.json` |
| `stats.py` | 샤프·PSR·DSR·정상 부트스트랩·Ledoit-Wolf·Holm·PBO(CSCV)·귀무모형 |
| `live.py` | 실시간 모의매매 (업비트·바이낸스·비트스탬프), 월간 재학습 |

## 5. 실행

```bash
pip install -r requirements.txt

# 전체 재현 (4코어 약 1시간)
python -m btc.walkforward budget          # 학습 스텝 수 (이미 2000으로 고정됨)
python -m btc.walkforward all             # P0×10, 격자, 절제, 귀무모형
python -m btc.evaluate --window dev       # 2017~2024
BTC_LOCKBOX_OPEN=1 python -m btc.evaluate --window full   # 2017~2026-09 (잠금 구간 포함)

# 테스트
python -m unittest discover -s tests -v                    # 빠른 테스트 (1분 이내)
BTC_SLOW_TESTS=1 python -m unittest tests.test_btc_controls -v   # 합성 대조 실험 (약 10분)

# 데이터 새로 만들기 (선택)
git clone https://github.com/ff137/bitstamp-btcusd-minute-data
python -m btc.data build --src bitstamp-btcusd-minute-data
```

### 실시간 모의매매

```bash
python -m btc.live export                 # 워크포워드 반복 0의 최신 모델을 data/btc/models/ 로 (이미 들어 있음)
python -m btc.live run --venue upbit      # 4시간마다 판단 (업비트 KRW-BTC, 비용 0.10%)
python -m btc.live once --venue upbit     # 한 번만 (cron·작업 스케줄러로 4시간마다 00:00:20 UTC 등)
python -m btc.live status
python -m btc.live retrain --src bitstamp-btcusd-minute-data   # 매월 1일 (먼저 git pull)
```

- 처음 실행하면 1시간봉 12,000개(약 500일)를 받아 지표를 채운 뒤 마지막 봉부터 판단합니다.
- **실제 주문은 넣지 않습니다.** 판단·가상 체결·가상 자산만 `data/btc/live/`에 기록합니다.
- 업비트는 원화, 백테스트는 달러(비트스탬프) 기준입니다. 지표는 가격 수준과 무관하게 만들었지만
  환율·김치프리미엄은 백테스트에 반영되지 않습니다.
- 매수·보유와 기준전략 B0~B6도 같은 비용으로 나란히 모의 운용해 비교합니다.

## 6. 알아둘 한계

- 강화학습 에이전트가 매수·보유를 이긴다는 것은 **증명되지 않았습니다** (결과는 `btc.html`).
- 잠금 구간(2025-01 ~ 2026-09)은 완전히 깨끗하지 않습니다 — 설계 단계에서 그 기간 시장 통계
  (매수·보유 CAGR −6%, 최대낙폭 −53%)를 봤습니다. 진짜로 깨끗한 검증은 2026-09-25부터의 모의매매 기록뿐입니다.
- 비트스탬프 한 거래소 데이터입니다. 거래량이 적은 소액 계좌 가정(시장 충격 없음, 전량 체결)입니다.
- 매수·보유 대비 우위를 통계적으로 확인하려면 샤프 차이가 약 0.6 이상이어야 합니다(9.7년 기준).
  "유의하지 않음"은 "우위가 없다"가 아니라 "증거가 없다"입니다.

투자 권유가 아닙니다. 판단과 결과는 투자자 본인에게 있습니다.
